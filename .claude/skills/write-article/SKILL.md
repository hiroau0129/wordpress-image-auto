# ネズミ駆除ランキング記事 執筆スキル

## 文字数・文体の鉄則

- **本文文字数：12,000〜15,000文字**（Markdown記号・HTMLタグ・AFFFIプレースホルダー除外）
- **文体：「です・ます」調で全文統一**（「だ・である」禁止）
- **1段落は最大6文まで**（表・リスト・吹き出しは段落扱いしないのでOK）
- 執筆前に構成段階で文字数を概算し、範囲内に収まることを確認してから書き始める

---

## 導入部（タイトル直下）

**3段落構成・各段落68文字以内** が正解。

| 段落 | 役割 | 文字数目安 |
|---|---|---|
| 段落1 | 読者の悩みへの共感（具体的な症状・問い合わせ増加） | 40〜55文字 |
| 段落2 | このエリア固有の特徴を**一文で**（なぜ繰り返すかを予告） | 35〜55文字 |
| 段落3 | この記事で何がわかるか（比較軸・社数を告知） | 45〜65文字 |

### NG例（島根記事の失敗）

段落2〜4で「なぜ繰り返すか」を詳しく説明してしまった → 107・117・75文字に膨張。

**「なぜ繰り返すか」の詳細はH2-1の仕事。導入では予告するだけ。**

### OK例

```
島根県の住宅や農家で「天井裏に物音がする」「フンを見つけた」という相談が増えています。（43文字）

宍道湖・中海の水辺環境・伝統建築・農村住宅の三重構造が重なる島根は、繰り返す被害が起きやすいエリアです。（52文字）

この記事では島根の業者5社を、水辺ドブネズミ対応力・完全封鎖力・伝統建築対応力の3軸で比較します。（49文字）
```

構造のポイント：段落2は「〇〇の三重構造が重なる△△は、繰り返す被害が起きやすいエリアです。」の型で書く。詳細はH2-1の仕事なので予告に留める。

## 比較表（導入直後）

H2「【比較表】〇〇対応ネズミ駆除業者X社をN軸で比較」のテーブルを導入の直後に置く。

列：順位 / 業者名 / 評価軸1 / 評価軸2 / 評価軸3 / 保証

---

## H2構成の順序

| 順序 | H2タイトル | 内容 |
|---|---|---|
| 1 | なぜ〇〇の被害は「繰り返す」のか | 評価軸3つをH3で展開。末尾にアフィリCTA |
| 2 | 【各社詳細】〇〇対応X社の特徴と強みを徹底解説 | 1〜X位をH3で展開 |
| 3 | 〇〇に出るネズミの種類と侵入パターン | ドブネズミ・クマネズミ・ハツカネズミをH3で |
| 4 | 〜が陥る3つの失敗パターン | 失敗①②③をH3で |
| 5 | 〇〇でネズミが出やすい季節と駆除依頼のタイミング | 季節3つをH3で |
| 6 | 〇〇の保健所はネズミ相談に対応しているか | 保健所テーブル（管轄・機関名・電話） |
| 7 | 〜別｜業者の選び方 | 住宅タイプ別（一般住宅・古民家・農家・飲食店）をH3で |
| 8 | ネズミ駆除の費用相場（〇〇） | 物件種類別テーブル |
| 9 | よくある質問（FAQ） | 6問をH3で。冒頭に「タップすると回答が表示されます。」 |
| 10 | まとめ | 状況別おすすめテーブル＋締め文 |

---

## 各社セクション（H3）のフォーマット

H3タイトル：`### 【N位 業者名】〜（エリア固有の強みを一言で）`

1. **評価テーブル（3行×3列）**：評価軸 / 評価（◎○△）/ エリアでの強み
2. **説明段落**：業者の概要→エリア固有の強みを2〜3段落（各段落100文字以内推奨）
3. **強みテーブル（4〜5行）**：強み / エリアでの対応内容
4. **チェックリスト**：この業者が向いている読者（箇条書き4〜5項目）
5. **アフィリCTA**：`[AFFI:業者コード]`

この順序を5社すべてで統一する。

---

## まとめセクション

**構成：状況別おすすめ表 → 本文6文 → アフィリCTA（この順序を守る）**

**状況別おすすめ表**（5行程度）：状況 / おすすめ業者

**本文6文**（固定フレーム）：
1. 「迷ったらまず1位の〇〇に無料相談することをおすすめします。」
2. 1位業者が総合No.1の理由を一文で（評価軸◎・対応エリア）
3. 「ネズミは放置するほど繁殖が進み、1匹のメスが年間最大50〜60匹の子どもを産みます。」
4. 「「様子を見よう」という時間が、後々の施工費用を跳ね上げる原因になります。」
5. 「〇〇（症状）を発見したら、できるだけ早くプロに相談してください。」
6. 「〇〇のどの状況でも、プロによる正確な調査と完全封鎖が最短・最善の解決策です。」

**アフィリCTA**：`[AFFI:1位業者コード]`

装飾：黄色マーカー2〜3・赤太字1〜2・吹き出し1（CTA直前）必須

### NG例（島根記事の失敗）

テーブル前に4文・テーブル後に4文 = 計8文超。テーブルが先でなく後に来ていた。

→ テーブルを先頭に移動し、本文を6文に削って修正した。

## よくある失敗

| 失敗 | 正しい対処 |
|---|---|
| 導入に「なぜ繰り返すか」の詳細を書く | 導入は予告だけ。詳細はH2-1 |
| 段落が68文字を超える | 一文を分割して2段落に |
| 3段落超の導入になる | 段落1＝共感、段落2＝特徴予告、段落3＝記事告知の3段落に収める |
| 文体が「だ・である」に混在 | 全文「です・ます」で統一 |
| 文字数が12,000を下回る | FAQを6問、各社説明を200〜250文字/社で調整 |
| まとめが長文になる | 表を先頭に移動し、本文を6文に削る。説明を増やしたい場合は表の行を増やす |
| まとめでテーブルが後半に来る | 構成は「表→6文→CTA」の順。テーブルを先頭に持ってくる |
| 段落が7文以上になる | 表・リスト・吹き出しに切り出す |
